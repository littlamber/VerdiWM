# 本地自主研究闭环：产品决策与 IRG 审查

日期：2026-09-09。状态：设计提案与代码审查记录；尚未实现的新行为不能视为已交付能力。

## 已确认的产品边界

- 同时面向本地与托管部署，先完成本地/用户自有 GPU 服务器。
- 用户提供模型、数据、目标和预算，系统默认完成技术接入，尽量不要求用户编写配置。
- 系统先只读发现并展示接入与实验计划，用户确认一次后，按计划授权的资源和操作范围自动准备环境、修复接口、运行实验和归档。
- 已授权范围内的重试不重复询问；新的数据需求、目标歧义、预算增加或超出计划的行为需要说明原因。
- 首个真实验收模型、JEPA 的具体角色、数据、指标和计算/API 预算仍待确定；不能据此直接启动付费或 GPU 实验。

本记录细化现有自主研究设计，不替代冻结评测、预算、实验回执及证据边界。现有文档中“控制平面完成”不代表默认产品入口已完成真实端到端研究。

## 一个统一的研究原理

维护对目标模型行为及修复效果的可证伪解释，选择预算内最有决策价值的下一次实验，再用结果更新解释。

这依托于序贯实验设计、贝叶斯决策和反例引导精化的一般思想；这一组合本身不是已经证明的新理论贡献。VERDI 需要通过实验建立的贡献是：干预响应表示能否提高跨模型修复决策的效率，以及反例能否改善这个表示。

研究状态包含目标协议、实测响应、不确定性、候选机制解释和已结算证据。候选行动统一为诊断实验与修复实验：

1. 文献提供机制与适用假设；本地记忆提供效果、失败及边界。
2. 对同一观测保留竞争解释，避免把响应强度直接命名为根因。
3. 候选方法必须指出解释、目标模型中的实际作用位置、可观测预测和否证条件。
4. 选择能够改善最终修复选择的实验，综合预期效用、信息价值和成本。
5. 结果支持或反驳解释，触发方法修订或探针精化；不能只保存胜出的方案。

初期采用可审计的排序启发式，并单独评估其效果。不应在没有可信后验模型时声称计算了精确的信息增益或最优实验策略。信息价值必须与修复决策有关，不能奖励无关的不确定性下降。

机制组合是这个过程的一个结果，并非默认创新规则。组合必须有互补性或交互作用的预测，并通过 baseline、A、B、A+B 的消融区分贡献。开放方法生成允许提出已有方法目录外的实现；代码执行接口可以固定，科学方法集合不能被固定目录穷尽。

## IRG 的科学角色

IRG 应是面向修复选择的、任务与上下文相关的干预响应表示。它不是模型的全局能力上限，也不是从响应直接识别内部根因的工具。

需要检验的核心假设是：在机制语义、目标任务和数据条件可比时，响应相近的模型，其某类修复效果更容易预测。可用一个条件性的局部平滑假设表达：

`|effect(m, repair, context) - effect(n, repair, context)| <= L * distance(phi(m), phi(n)) + epsilon`

这是假设，不是由 IRG 的定义推出的定理。`epsilon` 包含表示遗漏和跨上下文误差，必须在未参与表示学习的模型与修复上估计。方法的可实施接口和数据条件也必须参与预测或准入。

大规模参数更新可能超出局部推理干预的预测范围，需要训练相关诊断和独立效果校准。测得局部上限只意味着给定探针、剂量、任务和预算范围内的表现边界。

## 已审查的代码与复现结果

1. `wmloop/geometry/model_irg.py:model_irg_distance` 按探针级 `support_mask` 的索引遍历坐标，但响应坐标按 outcome × probe 展开。当前只累计第一个 outcome 的坐标。
   - 使用 `tests/test_model_irg.py` 的资产构建有效文档，将第二个 outcome 的一条受支持坐标增加 100 并重新计算 IRG 标识，距离仍为 0。
   - 需要按所有 outcome 展开支持掩码，并测试后续 outcome 的变化。
2. `wmloop/geometry/irg.py:irg_distance` 和模型距离使用逐对方差作为分母。高不确定性会减小距离，该函数一般不满足三角不等式。
   - 一维响应 0、1、2，方差分别为 0、1000000、0，得到 d(0,2)=2，而 d(0,1)+d(1,2)≈0.002。
   - 它可作为统计差异分数，但不能直接被称为模型表示的数学度量。
3. 资产保存完整协方差，当前距离只使用对角项。需要明确重复间协方差与均值估计不确定性的区别，以及轨迹、种子间的相关结构。
4. `estimate_response_chart` 允许单次重复，并返回零样本协方差。单次观测应记为不确定性未估计，不能当成已知无噪声。
5. `G = J^T W J` 描述探针空间中的响应变化大小，不能独自保留修复方向。J 与 -J 产生同一个 G；当前保留有符号响应坐标是必要的。
6. `derive_irg_bottlenecks` 以 `abs(response)/(1+uncertainty)` 排序，适合提示敏感方向，不能单独区分有用的动作响应、脆弱性和动作忽略。应加入基线失败、干预语义、指标方向与竞争解释。
7. `detect_model_irg_collisions` 转入裸欧氏距离，而检索使用另一种距离；碰撞检测还需严格核对坐标语义、共享支持、效果上下文和已验证状态。
8. `compose_irg_asset` 的 goal schema 写死为 ACWM 像素指标。跨家族使用需要显式任务协议与版本化探针语义，不能让 JEPA 等模型继承不适用的采样器或像素评测假设。
9. 默认 dispatcher 未传入底层已有的 IRG 参数；hybrid 自动填入目标句作为检索 query，可能绕过 IRG 生成 query 的分支。
10. 默认未知文献 materializer 生成原样返回 tokens 的 surrogate。它必须限于接入检查，不能被计为真实方法实现或创新候选。

上述检查为只读代码检查及 CPU 内存中的数值复现，没有修改历史资产，也没有启动模型实验。

## 建议的最小数学修订

- 保留有符号响应，明确任务、探针语义、剂量、基线、数据切分及测量版本。
- 在固定且完整的兼容坐标空间内，用训练侧冻结的正定尺度矩阵定义距离；需要学习尺度时，只使用外层测试集以外的数据。
- 距离衡量点估计差异；测量不确定性另行用于效果预测、补测和弃权，不通过增大方差制造相似性。
- 该距离是响应表示上的度量；不同模型可能具有相同表示，不能声称是模型身份上的严格度量。
- 缺失探针不补成正常的零响应。对不完整模型采用预先固定的兼容子空间或单独的部分匹配分数，并报告覆盖；不同逐对交集不能宣称构成统一度量空间。
- 不为保持全局线性而不断缩小剂量。失败时在开发数据上选择局部曲线、单侧响应或新探针，再做独立验证；非线性不等于模型无可修复性。
- 版本化新表示和距离，旧证据保留原定义。重新回放检索/碰撞与论文分析，不能静默重算后混用结果。

## 面向用户的同一条执行路径

`模型/数据/目标/预算 → 只读发现与计划 → 一次确认 → 自动接入与运行自检 → baseline/IRG → 假设与实验选择 → 真实实现 → 配对筛选与独立确认 → 证据归档与下一轮`

技术接入与任务评测分离：系统自动识别和绑定接口，优先复用可信任务评测。没有适用评测时，可草拟评测方案，用用户能理解的指标和例子确认，不能继承不相关模型的评测以通过检查。

快体现在复用和调度：缓存版本绑定的接入与基线，按决策需要选择探针，先用低成本实验区分假设，保留确认预算。缓存必须检测模型、数据和评测漂移。

工作台应展示实测瓶颈假设、当前证据、方法实际改动、费用和结果，而非要求用户操纵内部协议文件。网络不可用、缺数据、不可支持接口和无提升都有可恢复的明确状态。

## 验收顺序

1. 修复 IRG 数值、语义及默认调用链问题，保留版本兼容与回放记录。
2. 在一个明确模型/任务上，从干净环境验证用户无需手写配置的真实闭环；再用不同家族验证接入可迁移性。
3. 冻结数据划分与总预算，对比随机搜索、常规调参、目标文本检索、静态特征、原始响应以及 IRG 方法；预算计入接入、探针、检索/API 和最终确认。
4. 分别留出模型、任务和修复族，检查效果预测、校准、覆盖与负迁移；探针/表示学习必须位于内层，外层用于最终报告。
5. 在相同预算下比较检索复用与证据驱动方法生成，验证候选实现生效、机制消融和独立复现。创新性需另外比较相关工作，不能由“不在本地库中”定义。
6. 比较加入反例前后的表示，要求外层选择遗憾改善且校准不过度退化。保留没有成功改进的运行，不以筛选后的案例宣称持续进步。

工程目标可以承诺为自动化流程与可复现证据。研究有效性需要用独立确认成功率、首次有效提升成本、最终效果、负迁移和用户人工介入次数来证明，不能承诺每个任意新模型都能在固定预算内获得提升。

## 本轮落地：研究状态与方法准入（2026-09-09）

前述审查条目是修复前的记录。IRG 坐标覆盖、距离版本和默认路由已在 `5c404ce` 修订。本轮实现以下通用控制平面能力，未加入 Wan/DROID 专用判断。

### 已接入的行为

- `wmloop/control/research_state.py` 提供内容绑定的状态和原子日志。`autonomous_pipeline` 从已绑定的 scheduler objective、evaluator metrics 和预算建立日志，记录 observe、hypothesize、select、implement、verify、remember、settled 或 blocked。入口无需新增用户配置。
- 输出目录中的 `research/research-state.json` 保存当前状态，`research/research-history/` 保存历史，`research/research-binding.json` 绑定输入。相同输入重开日志保留当前状态；中断重试显式记录 blocked → observe，继续复用执行器的原有回执。已结算的同一 pipeline 返回其已有 manifest。
- 日志是**决策过程的投影**，不是新的实验、预算或知识权威。剩余 GPU 预算未接入 ledger 时保持 null；`settled` 只表示这次执行流程结算，不表示模型提升。`refine` 有状态契约，但本轮未把它伪造为已执行的表示进化。
- `mechanism_hypothesis` 记录目标故障、因果假设、实际作用位置、预测、否证实验、所需能力、反条件、证据来源与新颖性分类。Method IR 对该对象一起计算摘要，校验来源 ID 与能力声明的一致性。旧 IR 仍可读取，但新 `candidate_ready` 开放方法必须提供机制契约；blocked/missing interface 方法不获得校准资格。
- 未知文献方法默认返回 `REAL_METHOD_IMPLEMENTATION_REQUIRED`。显式 `interface_smoke_only=True` 可保留接口测试回执，但原样返回输入的 surrogate 即使所有测试通过，也不能进入正式候选目录。automatic materialization 与下游候选编译同时限制这一边界。
- 新回执记录 `real_method_required_v2` 策略及 surrogate 标记。旧 materialization 回执需在新的输出目录重新验证，不能自动继承新策略的准入资格。文献 materialization 缓存绑定所选 work order 内容与评测输入，并检查 catalog 摘要，拒绝不同输入或模式之间的静默复用。

### 本轮未证明的能力

机制契约的形式有效，不证明其因果解释正确；`surrogate=False` 也不证明实现真实改变了预期机制。后续仍需目标侧实际改动检查、配对实验、机制消融与独立确认。

默认文献入口目前在缺少真实实现时明确阻断；本轮没有宣称它已经自动调用开放方法生成器、修复任意模型接口并获得提升。开放方法编译与主流水线研究状态已有接口基础，竞争解释的自动产生、诊断与修复的统一选择、真实方法生成到调度的完整桥接，以及反例驱动表示更新，仍需逐项接通并验收。日志中的空 hypotheses 必须保持为空，不能把检索词或现有模板文案冒充为已完成的机制推断。

### 验证范围

新增 CPU 回归覆盖阶段顺序、输入不可变性、预算越权拒绝、日志历史与恢复、绑定路径保护、机制来源和能力绑定、开放方法准入，以及 surrogate/旧回执隔离。pipeline 集成测试使用替代执行器检查流程连接，不产生模型效果证据。完整 wheel 构建和隔离安装检查用于验证公开分发。本轮不运行 GPU 研究，不改写已有实验效果或论文数字。
