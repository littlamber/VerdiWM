# 本地 HTTP 认证

Workbench 与 Campaign API 保持回环监听，但回环地址本身不能区分同机用户。
所有读取和写入 API 现在都要求 `Authorization: Bearer <token>`。
令牌由服务每次启动随机生成，保存在随机临时目录中：目录权限 0700，文件权限
0600，退出时删除；重启生成新令牌。终端只输出令牌文件路径，不输出令牌值。

## 浏览器

启动工作台后访问终端显示的本地地址。根据终端中的文件路径在自己的终端读取
令牌，粘贴到登录页。登录验证成功后，令牌只保存在该 origin、该标签页的
sessionStorage 中；API 请求通过 Authorization header 发送。
不使用 URL 参数、Cookie、localStorage 或控制台日志传递令牌。
服务重启或令牌失效后返回登录页。登录页和固定的 HTML/CSS/JS 界面资源公开，
其中不包含令牌、数据路径或实验结果；API 的读取与写入都需要认证。

## 程序调用

程序应从终端提示的令牌文件读取值，并设置 Authorization header。不要把真实
令牌写进命令行参数、项目配置、源码或共享日志；也不要把文件改成其他用户可读。
不要关闭 Host/Origin 校验来适配代理。接口只支持本地可信工作流，不是远程多租户服务。

同机其他普通用户无法读取该令牌文件，缺少令牌时 API 返回 401。
同 UID 的进程以及 root 仍可能获取凭据；该认证不替代操作系统账户隔离、
可信浏览器环境或候选代码容器隔离。启动用户不应运行不可信候选代码。

在共享机器部署时，启动终端和浏览器配置也应归属于同一可信用户，不把私有
令牌文件复制到共享目录。即使令牌文件路径被其他人看到，文件权限仍应阻止读取。
